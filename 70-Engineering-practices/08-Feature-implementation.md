# Feature implementation

1. Identify the school requirement, functional ID and relevant mockup.
2. Record a focused issue and concrete acceptance criteria.
3. Change the authoritative API contract first when its behavior changes; update generated consumers.
4. Implement the smallest coherent change and appropriate regression tests.
5. Exercise the actual screen and API with the relevant roles, including error and private-resource cases.
6. Review the code, documentation and test evidence, then release and verify the deployed result.

Documentation describes implemented behavior separately from requirements and proposals. A missing required feature remains visible until implemented and verified. Keep operational secrets and temporary agent notes outside the product documentation.
